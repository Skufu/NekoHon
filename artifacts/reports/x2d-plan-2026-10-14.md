# x2d — systematic form augmentation (plan; pre-registered before any x2d training)

Context: the x2c checkpoint closed 2026-10-14 (not adopted; verdict in
`x2-trial-2026-10-14.md`). x2d targets the classes that stayed broken in both
x2 and x2c, plus the x2c-session regressions. Design source:
`finetune-expert-review-2026-10-14.md` P2-1 + the session's measured failure
list. This file is the pre-registration: the gate below is written before any
x2d data exists.

## Measured targets

- Uncited answers on non-memorized forms (sealed suite, 10 draws): fragment
  `explain` / `why does`, bare `Time Series` / `Micro-Batch` / `Streaming` /
  `Event Streams`, order pair A (`batch vs streaming` both directions),
  `pipeliness`.
- Pin misses: source-systems (cited ch05-004, pin ch02-005), extracted-in-ETL
  (refusal or wrong chunk), ET typo (ch02-022 vs ch07-033).
- insert-only wrong chunk (every model; ch08-107 vs ch05-020) — accepted as a
  known bad card unless a training form happens to fix it.
- User style: greetings (`hey ...`) without tripping the reading repair.

## Build spec

- Answers: ~3 forms per topic from the measured classes — canonical wh-form,
  lowercase form, bare topic/heading, order-flip where the topic is paired
  (both directions), a small greeting-prefixed set. Named adds from the
  cross-review: `undercurrents of data engineering` (shorthand) and
  `change data capture` (bare; soft pin — preflight check required). Property
  asks (e.g. "latency of SSD") only where a source card exists.
- Teacher-captured through the shipped seam, verbatim-verified, tiered as
  today (gold = pin first-cited; soft-pin demotion = silver).
- Refusals: 54 unique questions (compose ~27 more through the same teacher;
  exact sentence only; same count and share as x2/x2c).
- Size target ≈ 360–400 rows; training steps = `ceil(6 * rows / 8)` so
  per-row exposure matches x2's level (epoch-based, not fixed 120).
- Hold-outs: bench (hash-pinned) + the sealed fragment suite (never
  near-match — the seal check runs before any upload); record the new hashes.
- Notebook: v6 checks carry over; single candidate run (no seed control
  unless asked); q4 + q8 export as today; upload file `…train-x2d.jsonl`.

## Pre-registered gate (before training)

1. Refusals: France + iops exact, 10/10 over 5 runs.
2. Sealed fragment suite, 10 draws: per-class pass ≥ the 7B's — the bar that
   stopped x2c (fragment 20/40, bare 50/50, order 40/40, trailing 30/30).
3. Loops: 0 length-stops in the suite and in the capped battery sweep (×5).
4. Battery: ≥ 19/21 across 3 runs (x2's best recorded; equal draws).
5. No new deterministic pin misses vs the x2c session's list (source-systems
   and ETL/ET fixed or unchanged; insert-only accepted as a known card).
6. The visible ten keep working: Location, DE Lifecycle, ddr4-flip answered;
   warrup refuses; revert seam `ANSWER_MODEL=qwen2.5:7b` unchanged.

## Build steps

1. Generate candidate forms (script) + retrieval preflight (pin stays in the
   shown passages; canonical form differs; no near-match with bench, the
   sealed suite, or the ten visible queries).
2. Teacher capture through the seam (local `qwen2.5:7b`, temperature 0) +
   verifier + contamination probe + seal check; record hashes.
3. Notebook: update filename + expected count; keep the v6 checks.
4. User runs Colab (A100/L4, one slot); import hash-first; run the gate above;
   verdict doc supersedes this file.
