# Pilot 40 — history rows written by the teacher (2026-10-24)

Question this run answers: can the 27B write multi-turn targets that actually
use the history, or do we get round 4 again (assembled rows that teach "ignore
the history")?

Verdict: **not ready to scale.** 29 of 40 pass an independent audit. The three
non-conversational classes are clean; the entity-relation class is 7/18, and the
dominant reason is that the question does not need the history at all.

Mix, scaled from the 200-row plan: 18 entity-relation, 10 premise-trap,

2. the final question is new, so the teacher writes its target with the history

## Teacher run

40/40 answered, 0 empty, 0 truncated. First four rows took 115-119 s each (cold
prompt cache), the rest 2-21 s. All ten trap rows returned the exact refusal
`Not in this book.`

## Mechanical gate — 40/40

Each check maps to a past failure:

- quote appears verbatim in one of the passages shown (`string` fold, not the
  chunk file) — round 4 answered the wrong passage;
- entity-relation quotes come from the target section, not the history;
- trap rows kept only on the exact refusal sentence;
- no duplicate of the 844-row corpus by message hash;
- final questions checked against hard-bench, wide-net, sealed and adrian for
  exact/near overlap (0 leaks).

## Audit — 29/40

| class | keep | drop | reasons |
| --- | ---: | ---: | --- |
| entity_relation | 7 | 11 | history_not_needed 5, unsupported 4, wrong_relation 2 |
| premise_trap | 10 | 0 | — |
| simplify | 6 | 0 | — |
| highlight | 6 | 0 | — |
| **total** | **29** | **11** | |

The audit checks what the mechanical gate cannot: does the cited sentence
support the gloss, does the answer address the final question, and would the
answer be equally correct with the history removed.

## What the failures mean

`history_not_needed` (5) is a design defect, not a model defect. The questions
name both sides explicitly ("How does Apache Hudi relate to object stores?"), so
the final passage alone answers them. The row still teaches "don't copy the
history", but not "use the history" — the exact gap round 3 exposed.

`unsupported` (4) is an answer defect: the gloss says more than the quoted
sentence does. Fixable in the generation prompt ("the gloss may only restate
the quoted sentence"), no new data needed.

`wrong_relation` (2) is the same defect seen from the other side: the quote is
about a nearby idea, not the named entity.

## Decision

Do not scale to 200. One more 18-row pass with two changes:

1. the follow-up uses an elided or pronominal subject ("How does it relate to
   X?"), keeping the same-section + two-shared-word rule so coreference is
   unambiguous — this makes the history load-bearing;
2. the teacher prompt says the gloss may only restate the quoted sentence.

Re-audit the same way. Scale only if entity-relation clears ~14/18.

## Cost

One A100 session, 40 generations, one stopped session. No local answer model
was loaded; only `nomic-embed-text` ran, for six highlight retrievals.

## Round 2 — follow-up that names the prior answer (same day)

Changed only the entity-relation class. The second question became
`How does {entity} connect to the sentence you quoted?` so the answer has to
reach back to turn 1 instead of restating the section.

| step | result |
| --- | --- |
| build | 18 seeds, `PILOT_ER_TEMPLATE=answer_ref` |
| teacher | 18/18 answered, 0 empty, one A100 session |
| mechanical gate | 18/18 (quote in target section, no dup, no leak) |
| audit | **9/18** |
| drop codes | history_not_needed 6, wrong_relation 2, unsupported 1 |

7/18 → 9/18 is not a fix. The drop code moved (unsupported fell from 4 to 1)
because the answers stopped making relational claims at all: the teacher
defines the new entity from the new passage and ignores "the sentence you
quoted". Under the audit's definition, the history was still not needed.

### What this establishes

Every turn re-sends the passages, and every passage carries its heading. Any
question that names its subject can be answered from that turn alone. The
history is load-bearing only when the question cannot be parsed without it —
an elided "explain that", "shorter", "why does that matter". That is the
shape of the 15 real follow-ups in
`datasets/followup-evil-train-2026-10-17.jsonl`, and the reason the ER class
keeps failing is that it is not that shape.

Decision: stop growing entity-relation. Either widen the real follow-up types
(register, shortening, re-check the previous claim) or accept that multi-turn
in this app mostly means "do not be distracted by history", which the 844-row
corpus already teaches.
