## Verdict

All three P1s reproduce red before the change and pass green after it. The
combined suite is 49 tests, OK. No success condition was relaxed: a complete
status still needs source/package identity, `child_exit_code == 0`, and at
least one required model, report, and log item, each carrying a SHA-256.

## P1-1 — real COMPLETE status rejected by the watchdog

Cause, confirmed: `_artifact_items` read legacy `artifact_paths` first, tagged
those paths `kind: "artifact"`, and de-duplicated by path, so the explicit
`artifacts[]` entry (`kind/role: model`, `format`, `local_name`) was dropped.
`_complete_valid` then found zero model items.

Change: `watch_training.py:546` now builds items from explicit `artifacts[]`
first (kind, hash, required, local_name) and uses `artifact_paths` /
`report_paths` / `log_path` only for paths the explicit list does not cover.
`log_path` is injected only when no explicit hashed log item exists
(`watch_training.py:570`), so a chunked log is not re-downloaded as an
unhashed original. Strictness is unchanged: `_complete_valid` still requires a
model, report, and log with hashes.

Red (before): `AssertionError: 'artifact' != 'model'` and watchdog
`AssertionError: 4 != 0` for the real complete status, chunked and unchunked
(`red-tests-before-fix.log:105,114,228`). Red also shows the failed/chunked
run downloading the unhashed root `job.log` beside its hashed chunks
(`red-tests-before-fix.log:123`).

Green: `probe-watchdog-interop.json` — complete chunked and unchunked
`watchdog_complete_valid=true`, watchdog exit 0, all downloaded hashes match,
download set equals the explicit items plus the hashed download manifest, and
the operational `log_path` is not an extra download when chunks exist.

## P1-2 — declared `sources` entries beyond the trio were ignored

Change: `load_plan` (`run_reviewed_job.py:144`) validates every declared
source entry (path + SHA-256, resolved against the plan directory) and still
requires `runner`, `install`, `deps`; `closure` (`run_reviewed_job.py:256`)
hashes every entry in `plan["sources"]`, not a hard-coded trio. The package
loop already covered every non-`generated` entry.

Red (before): a plan declaring the executed gate script under `sources` with
SHA-256 `000…0` passed `--check-plan` (`AssertionError: 0 != 2`,
`red-tests-before-fix.log:132`). Green: exit 2 `closure_invalid`, no guard
output, no manifest, no status file; the same plan passes when the hash is
correct; removing required `deps` still exits 2 `plan_invalid`.

## P1-3 — verify-then-use on the plan path

Change: `main` reads the plan once, verifies `--plan-sha256`, and passes those
exact bytes to `load_plan(args.plan, raw_plan)` (`run_reviewed_job.py:794`);
`load_plan` parses the supplied bytes and never opens the path when they are
given. `_plan_sha256` and the executed document are the same object.

Red (before), FIFO serving approved document A then swapped document B:
`AssertionError: 'job-swapped' != 'job-approved'`
(`red-tests-before-fix.log:177`). Green: `probe-plan-single-read.json` —
`status_job_uuid=job-approved`, `status_plan_sha256` equals the approved hash,
`fifo_documents_served=1`, `second_document_served=false`.

## Finite safeguards

- Duplicate critical train flags are rejected in the plan check: `--manifest`,
  `--contract`, `--preflight-report`, `--approval` must each appear once
  (`run_reviewed_job.py:243`), closing the driver-first / argparse-last
  disagreement. Red: exit 0 for all four; green: exit 2 `plan_invalid`, no
  execution.
- Handoff now publishes a sealed copy of `job.log` under `job_dir/handoff/`
  (`run_reviewed_job.py:477`) and hashes those bytes
  (`log_snapshot_path`, `log_snapshot_sha256`). The live log keeps growing
  after approval; the snapshot does not. The watchdog transfers the snapshot,
  not the live log: handoff test asserts exit 10, snapshot hash before and
  after approval is identical, and the live log hash differs.
- Terminal chunked logs are satisfied by the explicit hashed chunk entries;
  `log_path` is not downloaded again (`watch_training.py:570`).

Preserved without change: one-attempt `O_EXCL` marker and `attach_report`,
exact job/session/source/package identity, mandatory trusted plan SHA, no
whole-job timeout (no `timeout=` keyword; approval wait unbounded), checkpoint
salvage on post-train failure, strict safe download destinations
(`local_name` checks + resolved `relative_to`), own-session-only stop with
verified absence, and preflight handoff exit 10.
